# AGENTS.md — руководство для агентов, работающих с этим репозиторием

Проект: расширение `kion-music-scrobbler` с отображаемым именем `KION Music Scrobbler`.
Расширение отправляет факты прослушивания с `music.mts.ru` в Last.fm.
Chrome собирается с третьей версией манифеста, Firefox — со второй. Оба пакета собираются из одного кода.

## Команды

```powershell
pnpm install
pnpm dev              # Chrome, разработка с мгновенной перезагрузкой
pnpm dev:firefox       # Firefox, разработка с мгновенной перезагрузкой
pnpm build              # сборка Chrome в каталог .output/
pnpm build:firefox      # сборка Firefox в каталог .output/
pnpm zip                # архив Chrome для каталога расширений
pnpm zip:firefox        # архивы Firefox для каталога дополнений
pnpm typecheck          # проверка типов
pnpm test               # unit-тесты Vitest
pnpm test:watch         # unit-тесты в watch-режиме
pnpm format:check       # проверка форматирования
pnpm lint               # проверка линтером
pnpm icons              # пересобрать иконки из assets/icon-source.png
```

Порядок проверок перед завершением работы: сначала актуализировать `README.md` и `AGENTS.md` в том же наборе правок, если менялись поведение, селекторы, манифест или API. Затем `format`, затем `lint`, затем `typecheck`, затем `test`, затем `build` и `build:firefox`.

Новые зависимости устанавливать командой `pnpm add -Dw <pkg>`. Флаг `-Dw` обязателен. Причина описана в пункте 2 раздела «Важные замечания».

## Важные замечания

1. **Здесь PowerShell 5.1, а не bash.** Связки команд без `&&`. Зависимые команды соединять через точку с запятой с проверкой `if ($?)`. Каталог не менять внутри команды, для смены каталога использовать параметр `workdir`. Пути с пробелами брать в кавычки. Кириллица в выводе консоли может отображаться неверно. Причина — кодировка терминала, с файлами всё в порядке.
2. **Локальный файл `pnpm-workspace.yaml` удалять нельзя.** В нём указан список `packages` с текущим каталогом. В родительском каталоге находится посторонний файл рабочей области без такого списка. Без локального файла команды pnpm завершаются ошибкой. По той же причине команда `pnpm add` требует флаг `-Dw`.
3. **На чистой копии сначала выполнить `wxt prepare`.** Файл `tsconfig.json` расширяет файл `./.wxt/tsconfig.json`, которого нет до генерации. Без генерации команда `tsc` завершается ошибкой `TS5083`. В списке `include` должен оставаться файл `.wxt/wxt.d.ts`. Иначе не видны автоматически подключаемые имена WXT, такие как `defineBackground` и `defineContentScript`.
4. **Только относительные импорты, без алиаса `@/`.** Пакет `vite-tsconfig-paths` не разрешается на этапе `wxt prepare`, сборка завершается ошибкой `Cannot find module`. Такое решение уже проверяли, оно не подошло.
5. **Файлы попапа лежат только в подпапке** `entrypoints/popup/index.html`, `main.ts` и `style.css`. Если положить файлы `popup.html`, `popup.ts` и `popup.css` рядом, сборщик воспримет их как три точки входа с одним именем, и сборка завершится ошибкой.
6. **Осторожно с автоматической вставкой точек с запятой.** Точки с запятой здесь отключены настройкой `semi: false`. Инструкция, которая начинается со скобки, склеивается с предыдущей строкой и парсится как вызов. Пример такой склейки: `])` с новой строки и `(`. Такие конструкции запрещены. Правила ESLint `curly` и `no-ternary` вместе с ревью находят нарушения, но правило нужно учитывать уже при написании кода.
7. **Манифест задаётся функцией от `browser`.** Файл — `wxt.config.ts`. Поле `action` является ключом манифеста, а не разрешением. Иначе Chrome отклоняет пакет с ошибкой `Permission 'action' is unknown`. Firefox собирается со второй версией манифеста. Решение покрывает старые версии браузера. Поле `action` преобразуется в `browser_action`. Иконки при преобразовании теряются, поэтому они указаны вручную. Также заданы `gecko.id` и `data_collection_permissions`.
8. **Пакет `eslint-config-prettier` в конфиге стоит до блоков с правилами.** Если поставить его последним, он отключает правило `curly`, и правило перестаёт действовать без предупреждений. Правило `curly` со значением `"all"` с Prettier не конфликтует.
9. **Content-script находится в файле `kion-music.content.ts`:**
   - Селекторы разрешены только по `data-testid`. Классы CSS-модулей содержат хеши и меняются между сборками сайта, поэтому они запрещены. Время считывается только из `player-current-time` и `player-full-time`.
   - Функция `send()` обязана переживать синхронное исключение. Для этого используются одновременно `try/catch` и `.catch`. После перезагрузки расширения скрипт, оставшийся на странице, теряет контекст. Без защиты в журнале появляются ошибки `Extension context invalidated`. Такой скрипт завершает работу через `shutdown()`. Функция останавливает наблюдатели и таймеры и выставляет флаг `alive`.
   - Сообщение `NOW_PLAYING` отправляется только при реальном воспроизведении. Решение принимает функция `isPlaying()`. Иначе страницы альбомов попадали бы в статистику по заголовку вкладки. Трек опознаётся связкой `artist|track` без длительности. Длительность подгружается позже старта, и её учёт давал бы повторную отправку `updateNowPlaying`.
   - Отсутствие медиа-элементов на странице — нормальная ситуация. Плеер сайта выводит звук через WebAudio. Прогресс для `<audio>` берётся из события `timeupdate`, для WebAudio — из счётчика страницы с метками `player-current-time` и `player-full-time`. Событие `ended` отправляет `STOPPED` для корректного повтора трека.
   - Фоновая иконка показывает число очереди (`N`/`99+`), при отсутствии сессии — `?N`. Успешный flush при пустой очереди возвращает иконку в онлайн. Очередь синхронизируется при старте браузера. Длительность передаётся в Last.fm. Повтор трека определяется по откату времени назад более чем на 5 секунд. Порог ограничен диапазоном 10–100. Опрос входа выполняется только фоновым таймером, таймера в попапе нет.
   - Входы со страницы валидируются в фоне (`sanitizeMeta/sanitizeTimes/sanitizeTimestamp`). Пустые строки, мусорные числа (`NaN`/`Infinity`), длительность больше 12 часов и метки старше 30 дней отбрасываются с варном `drop invalid input`. Варн троттлится до одного в минуту. Форма сообщений проверяется до вызова хендлеров.
   - Блоклист исполнителей хранится в `local:blockedArtists` (`blockedArtistsItem`, функции `normalizeArtistName/addBlockedArtist/removeBlockedArtist/isArtistBlocked`). Сравнение — вхождение нормализованной записи в нормализованную строку исполнителя (трим, нижний регистр, схлопнутые пробелы), кап 500 записей. Пустые записи не матчатся никогда, записи короче 2 символов — только точное совпадение. Проверка выполняется в фоне в `onNowPlaying` (до `updateNowPlaying`, `current` сбрасывается) и в `onProgress`. Заблокированным не отправляется вообще ничего. Прод-лог — `<имя> skipped by filter` (имя исполнителя разрешено, название трека — нет), троттлинг минута.
10. **Правило стиля, за соблюдением следит ESLint.** Ветвления и циклы записываются только в блочной форме со скобками. Тернарные операторы запрещены. Операторы `?.` и `??`, а также стрелочные функции в колбэках разрешены, потому что это не ветвления. Методы `map`, `filter` и `sort` разрешены, потому что это преобразования данных, а не циклы.
11. **Логи двух уровней.** Диагностика с именами треков и процентами — только для сборок в разработке внутри проверок `import.meta.env.DEV` (функции `debugLog/mergeDebug/noteResult`). Минификатор удаляет такой код из выпускной сборки. Строка диагностики в попапе в выпускной сборке скрыта. Журнал воркера (`logInfo/logWarn/logError` с тегом `[kion-music-scrobbler]`) работает всегда, включая прод: писать туда только коды и счётчики (`{ sent, left }`, `{ code }`); имена треков запрещены, исключение — имя исполнителя в строке `<имя> skipped by filter`. Тики `PROGRESS` не логировать. Пустых `catch {}` без реакции быть не должно: в воркере — лог (`logWarn/logError`), в попапе — видимая пользователю реакция (текст ошибки, `flashButton` на 2 секунды); исключения — best-effort пробуждения (`SETTINGS_CHANGED`, `AUTH_CHECK_NOW`, закрытие протухшего таба, `alarms.clear`), где повтор покрывается алармом или ререндером. Варны воркера троттлить (для тулбара — минута).
12. **Ручное тестирование.** Распакованное расширение загружается из каталога `.output/chrome-mv3` через пункт «Load unpacked». Для Firefox выбирается файл из каталога `.output/firefox-mv2` через пункт «Load Temporary Add-on». После каждой перезагрузки расширения нужно перезагрузить вкладку `music.mts.ru`. Прежний скрипт на странице после этого не работает. Порог для быстрой проверки — 10 процентов, трек нужен длиннее 30 секунд.
13. **Правки через Edit.** Сначала прочитать файл инструментом Read. Строка `oldString` должна совпадать с текстом файла точно, включая отступы. Если из-за кириллицы совпадение не находится, использовать в качестве опорных фрагменты из латинских символов и сверять результат побайтово.
14. **Доки и вопросы.** `README.md` и `AGENTS.md` держать в синхроне с кодом всегда, когда меняются поведение, селекторы, манифест или API. Любые правки (код и доки) выполнять только после вопроса пользователю и явного «делай».

## Имена

| Сущность                           | Значение                     |
| ---------------------------------- | ---------------------------- |
| Отображаемое имя                   | `KION Music Scrobbler`       |
| Package id / имена zip             | `kion-music-scrobbler`       |
| Папка проекта                      | `kion-music-scrobbler`       |
| Идентификатор расширения в Firefox | `kion-music-scrobbler@local` |

Версионирование — CalVer вида `YYYY.MM`. Месяц записывается двумя цифрами. Повторный релиз в том же месяце получает счётчик третьей частью, например `2026.10.1`. Каталоги расширений принимают в версии только цифры. Буквы запрещены.
