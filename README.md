# KION Music Scrobbler

Расширение для Chrome и Firefox, которое отправляет факты прослушивания с [music.mts.ru](https://music.mts.ru) в [Last.fm](https://www.last.fm). Сообщение `track.updateNowPlaying` уходит при старте трека, сообщение `track.scrobble` — после прослушивания заданной доли трека.

## Возможности

- Работает только на `music.mts.ru`, остальной интернет не затрагивает.
- Порог скроббла задаётся от 10 до 100 процентов, по умолчанию 50 процентов. Применяется мгновенно, без кнопки «Применить».
- Офлайн-очередь хранит до 1000 треков. Новые треки вытесняют старые. Если API Last.fm недоступно, треки копятся и синхронизируются позже. Синхронизация выполняется автоматически каждые 5 минут, при старте браузера или по кнопке «Синхронизировать» (при недоступности фона кнопки показывают «Нет связи с фоном»). Очередь показана плоским списком в попапе. Пока очередь пуста, раздел скрыт. Кнопка «Очистить» спрашивает подтверждение.
- Недоступность API видна сразу: жёлтая рамка иконки и число очереди (`3`, `99+`). Значок `?` (`?3`) означает, что требуется повторный вход.
- Ключ и секрет Last.fm вводятся один раз и в код не вшиваются. Вход через браузер завершается автоматически, вкладка сайта при этом закрывается.
- Треки короче 30 секунд не скробблятся. Этого требуют правила Last.fm.
- Список «Не скробблить исполнителей» исключает выбранные группы полностью: ни `updateNowPlaying`, ни скроббл не отправляются. Достаточно вхождения названия в строку исполнителя (коллаборации вида «Wildways, TRITIA» тоже режутся), регистр и лишние пробелы не важны.

## Стек

| Слой                     | Технология                                                                                                            |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| Сборка                   | WXT 0.20 + Vite 6. Один код собирается в пакеты `chrome-mv3` и `firefox-mv2`                                          |
| Язык                     | TypeScript 5, `strict`, `target ES2020`. Поддерживаются последние 10 версий браузеров                                 |
| UI попапа                | Vanilla TS + Tailwind CSS 4 + DaisyUI 5. Фреймворки не используются                                                   |
| Пакетный менеджер        | pnpm                                                                                                                  |
| Качество                 | Prettier с плагинами tailwind и sort-imports. ESLint с правилами `curly: all` и `no-ternary`. Проверка `tsc --noEmit` |
| Подпись запросов Last.fm | `blueimp-md5`. Подпись `api_sig` вычисляется этой библиотекой, потому что WebCrypto не поддерживает MD5               |
| Иконки                   | Node + `sharp` из файла `assets/icon-source.png`                                                                      |

## Быстрый старт

```powershell
pnpm install
pnpm dev              # Chrome, разработка с мгновенной перезагрузкой
pnpm dev:firefox       # Firefox, разработка с мгновенной перезагрузкой
```

Загрузка распакованного расширения. Chrome: открыть `chrome://extensions`, включить режим разработчика, выбрать «Load unpacked» и указать каталог `.output/chrome-mv3`. Firefox: открыть `about:debugging#/runtime/this-firefox`, выбрать «Load Temporary Add-on» и указать файл из каталога `.output/firefox-mv2`. Пакеты для каталогов собираются командами `pnpm zip` и `pnpm zip:firefox`. К пакету для каталога дополнений Firefox прикладывается архив исходного кода `-sources.zip`.

> После каждой перезагрузки расширения перезагрузите вкладку `music.mts.ru`. Иначе прежний скрипт на странице работать не будет.

## Подключение Last.fm

1. Создайте API-аккаунт на `last.fm/api/account`. Получите `API key` и `Shared secret`.
2. Вставьте их в попап расширения, нажмите «Войти через браузер» и разрешите доступ на Last.fm.
3. Расширение само завершит вход и закроет вкладку. Для проверки поставьте порог 10 процентов и проиграйте трек длиннее 30 секунд.

## Структура

```
entrypoints/
  background.ts          # скроббл, очередь, повторные отправки, иконка, опрос входа
  kion-music.content.ts    # определение трека и прогресса на music.mts.ru
  popup/                 # index.html + main.ts + style.css. DaisyUI используется только в этом каталоге
utils/
  lastfm.ts              # подпись api_sig, getToken/getSession, scrobble/nowPlaying
  storage.ts             # схема хранилища storage.local. Хранятся порог, ключи, сессия, очередь и блоклист
  types.ts               # QueuedTrack, сообщения, PendingAuth, DebugInfo
public/                  # иконки. Обычные варианты и варианты offline с жёлтой рамкой
scripts/make-icons.mjs   # генерация иконок
assets/icon-source.png   # исходник иконки
```

## Зафиксированные архитектурные решения

1. **Один код — два каталога.** WXT собирает пакеты `chrome-mv3` и `firefox-mv2`. Firefox собирается со второй версией манифеста. Так покрываются старые версии браузеров. Фоновые скрипты третьего манифеста поддерживаются только свежими версиями, а цель — последние 10 версий.
2. **Никаких UI-фреймворков.** Попап маленький, поэтому используются vanilla TS и DaisyUI. Размер пакета меньше, политика безопасности содержимого проще.
3. **Только относительные импорты.** Алиас `@/` не разрешается на этапе `wxt prepare`. Такое решение уже проверяли, оно не подошло.
4. **Фоновый скрипт работает по событиям.** Постоянных таймеров нет. Скрипт запускается при получении сообщений от content-script и по сигналам таймера. Повторная отправка очереди выполняется по таймеру каждые 5 минут и однократно при старте браузера. Таймер создаётся только при непустой очереди. Опрос входа выполняется только фоновым таймером, таймера в попапе нет.
5. **Очередь хранит до 1000 треков.** Новые треки вытесняют старые. Отправка идёт от старых треков к новым, до 50 треков в запросе. Это ограничение Last.fm. Повторно отправляются только треки, не доставленные из-за ошибки сети либо кодов 11 и 16. Код 9 означает, что требуется повторный вход. Успешный flush при пустой очереди возвращает иконку в онлайн. Счётчик отправленных учитывает только принятые (`accepted`), проигнорированные (`ignored`) видны в диагностике. Остальные ответы, включая фильтры `ignored`, отклоняются с записью причины. Такие треки в очередь не попадают.
6. **Трек опознаётся связкой `artist|track` без длительности.** Длительность подгружается позже старта трека. Её учёт приводил бы к повторной отправке `updateNowPlaying`.
7. **Определение трека идёт по цепочке источников.** Порядок источников: MediaSession, дерево страницы по `data-testid`, заголовок вкладки. Селекторы разрешены только по `data-testid`. Классы CSS-модулей нестабильны. Сообщение `NOW_PLAYING` отправляется только при реальном воспроизведении. Решение принимает функция `isPlaying()`. Иначе страницы альбомов тоже попадали бы в статистику. Входы со страницы валидируются в фоне: пустые строки, мусорные числа, длительность больше 12 часов и метки старше 30 дней отбрасываются. Пропущенный `NOW_PLAYING` восстанавливается по `PROGRESS` с честным `timestamp` (`now - currentTime`). Повтор трека без паузы определяется по откату времени назад более чем на 5 секунд. Скрипт, оставшийся на странице после перезагрузки расширения, завершает работу через `shutdown()` без ошибок.
8. **Плеер без медиа-элементов — обычная ситуация.** На music.mts.ru нет элементов `<audio>` и `<video>`. Звук выводится через WebAudio. Поэтому прогресс для WebAudio берётся из счётчика страницы с метками `player-current-time` и `player-full-time`, а для `<audio>` — из события `timeupdate`. Событие `ended` отправляет `STOPPED`.
9. **Last.fm вызывается строго по документации.** Данные запрашиваются в формате JSON, разбор XML не используется. Подпись `api_sig` вычисляется без параметра `format`. Сообщение `updateNowPlaying` повторно не отправляется. Одиночный скроббл использует плоские параметры, пакетные запросы — индексированные. Длительность трека передаётся в обоих видах запросов.
10. **Ключ приложения не вшивается.** Значения `API key` и `secret` хранятся в хранилище `storage.local` пользователя и вводятся один раз. Причина в том, что вшитый ключ становится публичным. Пакет расширения представляет собой открытый архив. Общий для всех ключ делит на всех ограничения и риск блокировки.
11. **Требования Firefox соблюдены.** Указаны идентификатор `gecko.id` и разрешение `data_collection_permissions` с типом данных `websiteContent`. Передача содержимого сайта в Last.fm составляет суть работы расширения. Иконки `browser_action` заданы явно, потому что WXT теряет их при преобразовании.
12. **Поле `action` является ключом манифеста, а не разрешением.** В списке `permissions` находятся только `storage` и `alarms`. Иначе Chrome отклоняет пакет.
13. **Логи двух уровней.** Диагностика с именами треков — только в сборках для разработки (`import.meta.env.DEV`). Журнал воркера (`[kion-music-scrobbler]` в консоли service worker / background) работает и в проде, но пишет только коды и счётчики, без названий треков (исключение — имя исполнителя в строке `<имя> skipped by filter`). Тики прогресса не логируются. Строки диагностики в попапе в выпускной сборке нет.
14. **Требования к стилю кода.** Ветвления и циклы записываются только в блочной форме со скобками. Тернарные операторы запрещены. За соблюдением следят правила ESLint `curly: all` и `no-ternary`. Prettier отвечает только за форматирование. Порядок импортов такой: сначала внешние пакеты, затем файлы проекта, затем стили.
15. **Изоляция от посторонней рабочей области.** В корне проекта лежит собственный файл `pnpm-workspace.yaml`. Список `packages` в нём содержит текущий каталог. Файл нужен, потому что в родительском каталоге находится посторонний файл рабочей области. Без локального файла команды pnpm завершаются ошибкой.

## Версионирование

Версионирование — CalVer вида `YYYY.MM`. Месяц записывается двумя цифрами. Текущая версия хранится в `package.json`. Сборщик WXT подставляет её в манифесты и в имена архивов. Повторный релиз в том же месяце получает счётчик третьей частью, например `2026.10.1`. Каталоги расширений принимают в версии только цифры. Буквы запрещены.
